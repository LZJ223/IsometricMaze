# 2026-11-07｜主场景与游戏循环

本次新增正式游戏入口，复用三个核心类，运行流程不依赖白模脚本。未接入玩家、目的地或磁盘存档。

## 场景与资源

- `scene/game.tscn`：根节点挂载 `script/system.gd`，直接子节点为 `GeometryView`、`ParallelMapView`、`UIGame`。
- `scene/ui_game.tscn`：根节点为 `CanvasLayer`，直接子节点为转换按钮、整轮撤销按钮、编辑菜单。菜单含画笔、橡皮、单格撤回、上面、左面、右面六个按钮。
- `script/system.gd`：统一管理随机初态、视图切换、相机、绘图、编辑历史、循环历史和重建线程。
- `project.godot`：主场景切换到 `res://scene/game.tscn`。

界面使用普通 `Control` 分组，位置不由脚本修改，可以在编辑器中移动。绑定依赖 UI 场景内的唯一名：`ConvertButton`、`UndoButton`、`EditMenu`、`BrushButton`、`EraserButton`、`UndoEditButton`、`TopButton`、`LeftButton`、`RightButton`、`StatusLabel`、`BudgetLabel`。调整布局时保留这些唯一名及其场景归属。

## 状态与操作

- 几何状态：非 UI 区域按住左键或右键拖动相机，松开后吸附到最近的上方四向正等轴测视角。转换按钮进入编辑，撤销按钮回退一个成功循环。
- 编辑状态：画笔对已有三角格改色，对允许范围内的空白格添加；橡皮删除三角格。点击或拖动均可编辑，每次有效格修改消耗一次额度，默认每轮十次。
- 单格撤回恢复修改前的状态并返还额度；外层撤销按钮取消整轮编辑并恢复进入前的几何体和视角。
- 重建状态：使用数据副本启动工作线程，锁定交互。主线程接收结果，再复查完整投影、边界和共面连通性。
- 只自动提交已认证的最优解。无解保留目标图；预算耗尽或存在未证最优的有效解时，通过原转换按钮提高预算重新搜索。重试预算逐次加倍，上限为基础预算的八倍，不恢复搜索栈。
- 只有成功提交才写入循环历史，默认最多保留三十轮。取消、失败和单纯观察不会写入历史。

## 编辑器配置

`system.gd` 导出允许体素边界、初始体素数量、随机种子、编辑与历史上限、旋转灵敏度、吸附时长、视图留白和重建预算。种子为零时每次启动随机生成，其他值用于复现初态。移动 UI 后可调整 `view_margins`，为控件预留画面空间。

三维相机与二维画布使用同一可视区域，在四个标准方向下保持投影位置和比例一致。编辑不重排网格坐标，也不因增删三角格立即重新适配画面。

## 验证

入口为 `test/validation/game_validation.gd`，可用 Godot 的 `--script` 参数运行；加 `-- --capture --output <绝对目录>` 可保存渲染截图和结果 JSON。

本轮在 Godot 4.7.2、GL Compatibility 环境中完成 **148 项检查，零失败**，包括实际 OpenGL 渲染截图。覆盖场景层级、随机连通初态、固定种子、四向投影对齐、真实按钮与拖动事件、吸附、绘制与撤回、编辑额度、后台线程、投影轮廓扩张和收缩、整轮回退、无解、预算耗尽及空图适配。

三个核心脚本 `geometry.gd`、`parallel_map.gd`、`geometry_reconstructor.gd` 未修改，已通过修改前后的 SHA-256 对照确认。
